# Baseline 2026-11-08

First runtime evidence for dndm at the pin. Roster task R1-04. No source edits; the worktree held only untracked `docs/` before and after.

**Result: builds and vets clean; non-race tests pass; `go test -race` fails in 2 of 5 tested packages with 55 data-race reports (23 unique access pairs).** The codec and stream packages that [DND-001](tickets/DND-001-bounded-stream-framing.md) touches are race-clean.

## Pre-run inspection (static, nothing executed)

- `Makefile`: `test` = `go test ./... -vet=all -v -count 3` (no `-race`). `vulncheck` and `install-tools` run `go install` → **not run** (roster rule 4). `docker-*`, `proto` (`buf`), `mocks` (`mockery`), `run-bench` → not run (external tools/containers, not needed for a baseline). `build-<example>` recipes build `./cmd/<example>`, but the repo has no `cmd/` directory, so `make build` cannot work as written (static reading; not run).
- `examples/embedded/Makefile`: plain `go build`/docker targets; covered by `go build ./...`; docker targets not run.
- Tests: 11 `_test.go` files in 5 packages. No `net.Dial`/`Listen`, serial port, localhost or port literal in any test (grep, no matches). `network`/`network/stream` tests use mocks; `x/bus` remote tests connect two `remote` endpoints over in-process `io.Pipe`. **Nothing needed skipping** for network or hardware.
- Packages without tests: `endpoint/{direct,mesh,remote}`, `network/{net,serial}`, `errors`, `testutil`, `types/*`, all `examples/*`. Their behaviour is exercised only indirectly (direct/remote via `x/bus`) or not at all (mesh, net, serial).

## DND-001 probe

Throwaway `main` package calling exported `codec.ReadMessage`/`codec.DecodeMessage` with in-memory readers; source deleted after the run, output kept ([dnd001-probe.txt](baseline-logs/dnd001-probe.txt)).

| Case | Input | Observed |
|---|---|---|
| P1 | valid 57-byte frame, `bytes.Reader` | ok |
| P2 | same frame, `iotest.OneByteReader` | `not enough bytes`: valid frame rejected |
| P3 | same frame, `iotest.HalfReader` | `not enough bytes`: valid frame rejected |
| P4 | preamble, declared size 0 | `EOF`: `buffers.Get(0)` returns nil and `bytes.Reader.Read(nil)` at end of input returns `io.EOF`. [INFERENCE] with bytes still queued it returns `0, nil`, so `ReadMessage` would yield a nil buffer and `DecodeMessage` would panic; not run |
| P4 | preamble, declared size 1 or 3 + that many bytes | `ReadMessage` ok, then **`DecodeMessage` panics**: `index out of range [3] with length 1` / `3` |
| P5 | body = valid header-length + header, no message-length field | **`DecodeMessage` panics**: `index out of range [3] with length 0` |
| P6 | preamble declaring 2^28 bytes, then EOF | `EOF` after **256 MiB `TotalAlloc`** |

Not observable without a test seam: the pooled buffer that `ReadMessage` drops on body-read error or short read (`codec/codec.go:100–107`). Still a static finding.

[INFERENCE] `endpoint/remote/messages.go:37–41` calls `conn.Read` with no `recover` anywhere on that path (the only `recover()` in the repo is `stream.go:181`), so a peer that sends P4/P5 bytes should crash the whole process, not only the connection. Not executed end to end.
